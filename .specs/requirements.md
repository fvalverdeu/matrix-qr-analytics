# Requirements

## Project Overview

Build a solution composed of two independent REST APIs communicating through HTTP.

The first API is implemented using Go and Fiber and is responsible for QR decomposition.

The second API is implemented using Node.js and Express and is responsible for calculating statistics from the decomposition results.

The solution must be containerized using Docker.

---

# Constraints

- Go + Fiber
- Node.js + Express
- Docker
- HTTP communication between services
- No persistence layer

---

# Functional Requirements

## FR-001 - QR Decomposition

The Go service shall expose an endpoint that receives a rectangular matrix represented as an array of arrays of numbers.

Example:

```json
{
  "matrix": [
    [1, 2],
    [3, 4]
  ]
}
```

The service shall calculate the QR decomposition and generate:

- Matrix Q
- Matrix R

---

## FR-002 - Statistics Calculation

The Node.js service shall receive matrices Q and R.

The service shall calculate:

- Maximum value
- Minimum value
- Average value
- Total sum
- Diagonal matrix verification

---

## FR-003 - Service Communication

The Go service shall invoke the Node.js service through HTTP after QR decomposition is completed.

---

## FR-004 - Aggregated Response

The Go service shall return:

- Matrix Q
- Matrix R
- Statistics generated by the Node.js service

---

# Validation Rules

The matrix:

- Must be present.
- Must not be empty.
- Must contain only numeric values.
- Must be rectangular.
- Must contain at least one row and one column.

Invalid requests must return HTTP 400.

---

# Non-Functional Requirements

## NFR-001

Code must be organized using a layered architecture.

## NFR-002

Services must be independently executable.

## NFR-003

Configuration must be externalized through environment variables.

## NFR-004

Each service must run in its own Docker container.

## NFR-005

Communication between services must use JSON over HTTP.

## NFR-006

No database or persistence mechanism shall be implemented.

## Engineering Standards

### Source Control

The project must follow Git best practices.

Recommended branch strategy:

- main
- feature/\*

Examples:

- feature/go-qr-service
- feature/statistics-service

---

### Commit Convention

Commits must follow Conventional Commits.

Examples:

- feat(go): implement QR decomposition endpoint
- feat(node): implement statistics calculation
- feat(docker): add docker compose configuration
- docs: add architecture documentation
- test(node): add statistics service tests

---

### Clean Code

The implementation must follow clean code principles:

- Single Responsibility Principle
- Small and focused functions
- Meaningful naming
- Avoid duplicated logic
- Clear separation of concerns

---

### Error Handling

All APIs must:

- Return proper HTTP status codes
- Return consistent error responses
- Avoid exposing internal implementation details

---

### Configuration

Configuration must be externalized using environment variables.

Hardcoded URLs and ports are not allowed.

---

### Documentation

All public endpoints must be documented in the README.
